Run on the separate domain administration workstation, using the logged-on
domain account. No production AD tests have been run on the build machine.

Examples use example.test and dc.example.test. Replace them and the test OU DN
with your own domain/DC before running. No environment is preconfigured.

READ-ONLY DIAGNOSTICS (Windows PowerShell 5.1)
Copy tests/diagnose-samba-ad.ps1 to that workstation. Run:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\diagnose-samba-ad.ps1 -Server dc.example.test
Expected naming context: DC=example,DC=test
Expected DNS domain: example.test
The script reads RootDSE, all OUs/gPLink, GPOs via GroupPolicy, and SYSVOL.
For a selected Base Search OU, run again with:
  -BaseOU "OU=<dedicated-test-ou>,DC=example,DC=test"
For GPO LDAP attributes and SYSVOL version/scripts, add:
  -GpoGuid "<test-gpo-guid>"
No diagnostic command creates, changes, links or deletes AD objects.

MANUAL FUNCTIONAL TESTS (explicitly invoke each operation yourself)
1. Use a dedicated test OU, dedicated test GPO and Windows 11 test computer.
   Create the test OU through your normal administration tools if necessary.
   Do not select existing production policies for mutation tests.
2. Start the new portable application. Save Domain Controller as
   dc.example.test. Check RSAT and Test AD Connection in Settings.
   LDAP must report healthy despite Get-ADDomain still failing independently.
   GroupPolicy must be available for GPO management. Check the GPO list.
3. Browse OUs, select the test OU as Base Search OU, save and reload. Confirm
   only its subtree is displayed; include two configured bases if used locally.
   Check existing links and counts against GPMC. Test names with escaped commas,
   apostrophes and Unicode on the dedicated test OU if these are used locally.
4. Use the normal deployment wizard and your existing SMB repository to create
   a harmless test deployment, dedicated GPO and link to the test OU. Record
   the GPO name/GUID. The referenced deployment script stays on the repository.
5. Run diagnostics with -GpoGuid. Verify scripts.ini contains powershell.exe and
   the repository script path; the Scripts computer CSE/tool GUIDs are present.
   Confirm gpt.ini Version and LDAP versionNumber describe the same 32-bit value
   (a negative LDAP integer is interpreted as unsigned). The computer low word
   advances; the user high word stays unchanged.
6. In GPMC confirm policy readability, link status and computer Startup script.
   On the test computer run gpupdate /force, then reboot (Startup scripts run
   at computer startup). Check GroupPolicy Operational event log for errors
   and verify the harmless deployment's expected result/logs.
7. For preservation testing, use a SECOND dedicated GPO. In GPMC add an unrelated
   computer Startup script, Shutdown script and another computer setting/CSE.
   Record scripts.ini, CSEs and both versions. Use this GPO name with the normal
   application create/update operation to add its deployment. Confirm all
   pre-existing scripts/settings remain and the user version is preserved.
8. Explicitly invoke removal of the application's startup script for that test
   GPO. Confirm only its recorded entry/ownership file are removed; unrelated
   Startup/Shutdown scripts, CSE registrations and files remain. Confirm versions
   agree, indices remain contiguous and GPMC still reads the GPO. An ownership
   record missing/changed externally must cause a visible refusal, not deletion.
9. Unlink the test deployment in the app and verify the intended OU link alone
   is gone. Repeating unlink should succeed harmlessly. Delete only the dedicated
   test GPO through the application after reviewing its name.
10. With the DC setting empty on the domain-joined admin workstation, repeat
    read/list checks and confirm native PDC discovery works. Set the explicit
    DC again for normal use. Test the same read/write flow against a Microsoft
    AD test domain if available; this has not been locally validated either.
11. If your environment provides a safe way to confirm traffic, verify these
    operations succeed without TCP 9389 and without the ActiveDirectory module.
    Do not change production firewall rules solely for this test.

Record actual results, DC/client versions and logs. Compatibility remains
unverified until these integration tests pass. Remove dedicated test objects
and restore the test client's OU membership using normal administration tools.

LIMITATIONS
Legacy scripts created by older versions have no ownership marker. Automatic
startup removal refuses those GPOs; review/migrate manually on the admin machine.
Concurrent external GPMC edits are not locked by the app. Do not edit the same
test policy externally during an application write. LDAP and SMB are separate
services, so rollback is best effort and any incomplete rollback is reported.
